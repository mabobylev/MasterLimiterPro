# Внешний аудит True Peak

Из каталога проекта:

```sh
python3 tools/validate_true_peak.py \
  --test-binary build/MasterLimiterTests \
  --output-dir build/true-peak-audit
```

Скрипт требует установленный `ffmpeg` с `ebur128=peak=true`; каталог вывода
должен отсутствовать или быть пустым. Тестовый executable через
`MASTERLIMITER_EXPORT_AUDIT` формирует float32 WAV непосредственно из выхода
`processBlock`: SP/TP × 44.1/48/96/192 kHz × потолки −6/−1/0 dB × Fs/4,
детерминированный широкополосный шум и повторные импульсы. На каждой частоте
шума используется одинаковая начальная seed-последовательность для всех
режимов и потолков. После 120 ms сигнала экспортируются задержка процессора и
ещё 50 ms нулевого входа. `manifest.json` фиксирует параметры и длины.

Измеритель FFmpeg выводит True Peak с разрешением 0.1 dB; отчёт явно хранит
эту дискретность. TP на 44.1/48/96 kHz сравнивается с Limit + 0.1 dB. Для
Fs/4 SP fixture на тех же частотах проверяется чувствительность внешнего
измерителя: ожидается превышение потолка не менее чем на 0.5 dB. FFmpeg
пересэмплирует ebur128 true-peak до фиксированных 192 kHz, поэтому вход 192 kHz
не получает интерполяции и этот ряд только экспортируется и измеряется как
ограниченная справочная оценка; он не считается внешней TP-проверкой.

WAV, логи и `audit.json` остаются в `build/` (игнорируется Git). Аудит —
воспроизводимая внешняя проверка выбранных fixtures, не сертификация BS.1770,
не рендер DAW и не гарантия для всех сигналов или хостов. Независимый 16×
тестовый интерполятор проекта по-прежнему покрывает все четыре sample rate.
