# Приёмка в REAPER

Статус: подготовлена; запуск REAPER, прослушивание и подтверждение выполняет
пользователь. Автотесты процессора не считаются приёмкой VST3 в хосте.
Использовать отдельный тестовый проект и копию материала, без изменения
рабочего проекта. Записать версию REAPER, sample rate, размер блока и версию плагина.

## 1. Загрузка и сохранение — первая проверка

1. Создать тестовый проект, выставить 48 kHz. Импортировать знакомый stereo
   фрагмент 20–30 s с ударными и басом, поставить Master Limiter Pro последним FX
   на дорожке. Оставить фейдер дорожки/master на 0 dB, другие FX отключить.
2. У нового экземпляра проверить: Input 0 dB, Limit −1 dB, Lookahead 5 ms,
   Release 100 ms, Stereo Link 100%, Soft Clip OFF, True Peak OFF.
   В шапке ожидается задержка около 22.4 ms (1073 samples при 48 kHz).
3. Поставить Input +6 dB, Limit −3 dB, Lookahead 8 ms, Release 150 ms,
   Link 75%, True Peak ON; Soft Clip оставить OFF. Включить воспроизведение:
   waveform L/R и GR обновляются, ручки и подписи читаются. При остановке
   история удерживается; после закрытия/открытия FX накопленная история видна.
4. Сохранить проект, закрыть и открыть его снова. Проверить сохранение всех
   семи изменённых/выбранных настроек и воспроизведение. Не требовать
   восстановления истории waveform после полного пересоздания экземпляра.
5. Добавить второй экземпляр, изменить его Input и Limit. Проверить, что
   настройки первого не изменились. Сохранить/открыть проект ещё раз.

Сообщить: загрузка/сохранение OK или точный шаг, где поведение отличается.
Старый реальный проект проверять только на копии; синтетическая миграция
из unit tests не подтверждает восстановление автоматизации конкретного хоста.

## 2. Прослушивание и автоматизация

На копиях одного материала сравнить TP OFF/ON и Soft Clip OFF/ON.
Громкость для слухового сравнения выравнивать отдельным gain ПОСЛЕ плагина;
такой gain отключать перед измерением потолка. Не считать более громкий вариант
автоматически лучшим. Проверить атаки ударных, бас, хвосты и стереообраз.
При Link 100% громкий сигнал одного канала должен вызывать связанное ослабление;
при 0% возможно изменение образа из-за независимой обработки.

Записать плавную автоматизацию Input, Lookahead, Release, Link и Limit;
отдельно переключить TP и Soft Clip. Отметить щелчки, провалы или зависания.
У TP после включения есть прогрев 30 ms и кроссфейд 20 ms; резкое снижение
Limit и host bypass могут быть слышны. Bypass не ограничивает уровень.
Проверить несколько размеров audio block (например 64 и 512, если доступны).

## 3. Экспорт и задержка

- Render одной и той же области в WAV float32, stereo, без нормализации,
  без смены sample rate и без downstream gain/FX. Оставить хвост не менее 0.5 s.
  Фейдеры должны быть 0 dB. Сохранить параметры и название каждого варианта.
- Сравнить offline и realtime render при одинаковых исходных настройках и
  начальном состоянии; расхождение отдельно исследовать, не выдавать
  произвольный null-test допуск за гарантированное требование хоста.
- На низкоуровневом импульсе/сигнале ниже Limit, Input 0, Soft Clip OFF,
  TP OFF сравнить обработанный render и сухую копию с включённой PDC REAPER.
  При корректной компенсации транзиент не сдвигается на задержку плагина.
  Для TP ON фильтр меняет форму импульса: строгий null с dry не ожидается.
- Повторить сохранение и экспорт с двумя экземплярами; проверить начало,
  конец файла и отсутствие пропавших каналов/тишины/обрезанного хвоста.

## Внешний измеритель экспорта

Для конкретного файла можно сохранить полный журнал FFmpeg:

```sh
ffmpeg -hide_banner -nostats -i "render.wav" -af ebur128=peak=true -f null - 2> "render-meter.log"
```

Смотреть итоговый True peak/Peak (dBFS в логе измерителя), не Integrated LUFS.
Не путать его с sample peak. Это независимая оценка, не сертификация BS.1770.
На 192 kHz данный FFmpeg meter не даёт дополнительной интерполяции;
не использовать его как подтверждение межсэмплового потолка этой частоты.
Автоматический экспорт тестового процессора описан в TRUE_PEAK_AUDIT.md;
он отдельно от render VST3 внутри REAPER.
