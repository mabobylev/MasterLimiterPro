# Актуальные решения — 2026-10-17

## GUI

Ориентир — актуальный Source/PluginEditor.cpp проекта KickDuck1:
фон RGB(7,9,13), панели (16,19,25)/(11,14,19), тонкие серые рамки,
шрифт FontOptions, фиолетовые ручки, оранжевый вход, зелёный выход,
розовое подавление. Минимум 900×580, по умолчанию 1100×700,
максимум 1800×1100. Автоматические snapshots не открывают окно DAW.

## Основной limiter

Основная задержка — round(sampleRate × 0.020), неизменна при автоматизации
Lookahead. Полная задержка с выравниванием TP/SP/bypass приведена ниже.
Окно детектора включает текущий выходной sample и Lookahead вперёд.
Дерево максимумов работает в заранее выделенной памяти без аллокаций и
блокировок. Финальный clamp защищает sample ceiling от численной ошибки.
Link=0 даёт независимые gain envelope, Link=1 — одинаковое ослабление каналов;
промежуточные значения линейно связывают требуемые gain. Release экспоненциальный.
Input/Lookahead/Release/Link и потолок вверх сглаживаются за 20 ms; потолок
вниз действует сразу и может быть слышен. Host bypass не ограничивает сигнал
и не имеет отдельного кроссфейда, но сохраняет полную задержку.

RMS — средняя мощность каналов с постоянной 300 ms, без отмены противофазы.
Peak падает 24 dB/s; выходной hold держится 1 s и падает 20 dB/s.
GUI запрашивает reset атомарным флагом, накопителями владеет аудиопоток.

## INPUT и LIMIT — уточнение интерфейса

Ceiling переименован в LIMIT в GUI, помещён на правый край и окрашен
в зелёный (роль выходного сигнала). INPUT остаётся входным усилением,
поэтому название Threshold не используется. Диапазон INPUT не менялся:
−24…+24 dB, ноль в центре; теперь дуга рисуется от нуля в обе стороны,
положительные значения имеют явный знак +.

Чтобы расширить LIMIT до −6…0 dB без перенормировки прежних огибающих,
новый параметр LIMIT добавлен после первых пяти параметров. Исходный CEILING
с прежним ID/индексом/диапазоном −3…0 сохранён с названием Ceiling (legacy).
Новые экземпляры используют LIMIT; CEILING в них не влияет на обработку.
При загрузке старого PARAMETERS без LIMIT выбирается legacyLimitMode.
В этом режиме DSP и ручка LIMIT управляются прежним CEILING, включая
старую автоматизацию. Сохранение фиксирует режим отдельным свойством корня.
Таким образом старое значение normalized=0.5 по-прежнему даёт −1.5 dB,
а новый LIMIT при normalized=0.5 даёт −3 dB. Режим не переключается
из-за открытия GUI или движения ручки. Для нового диапазона в старом
проекте нужен новый экземпляр; конвертация огибающих не выполняется молча.
При восстановлении состояния с открытым GUI attachment переключается
на нужный параметр. Изменение проверено тестами старого/нового state,
roundtrip после повторного сохранения, старой автоматизации, нормализации,
предела −6 dB, положения LIMIT, нулевого центра и знаков INPUT.

## Отдельный режим Soft Clip — 2026-10-17

В новых экземплярах перед limiter нет постоянной нелинейности. Сначала
применяется Input gain; далее чистый сигнал или опциональный tanh поступает
в существующее окно детектора и задержку аудио. Ниже потолка, без ограничения,
чистый выход совпадает с задержанным входом с учётом Input gain.
Это не утверждение об отсутствии искажений при активном ограничении.

SOFTCLIP — новый bool-параметр, добавленный в конец списка (default OFF).
Остальные ID/индексы/диапазоны и VST3 UUID не менялись. При загрузке PARAMETERS
без SOFTCLIP в дерево добавляется явный PARAM SOFTCLIP=1: обе прежние схемы
(с LIMIT и без LIMIT) сохраняют tanh. Выбор OFF в старом проекте впоследствии
сохраняется как OFF. При prepare/reset и первом аудиоблоке smoothing
инициализируется сохранёнными значениями; учтена загрузка состояния хостом
после prepareToPlay. Во время работы переключение делает линейный кроссфейд
чистого/насыщенного сигналов за 20 ms, до общего детектора. Это сохраняет
контроль потолка; полная задержка тракта описана ниже.

В GUI добавлена кнопка SOFT CLIP в шапке, ON выделен оранжевым.
Автоматически включённое насыщение старого проекта видно на этой кнопке.
GR по-прежнему измеряет gain ограничителя, а не действие tanh.
У Soft Clip нет oversampling: гармоники и алиасинг не объявляются устранёнными.
Чистый режим не требует вычисления tanh, когда кроссфейд достиг OFF.
Умножение входа на gain защищено от переполнения float для экстремальных
конечных значений; NaN/Inf входа по-прежнему заменяются нулём.

Проверки: analytical null для clean и tanh при амплитуде синуса 0.7,
100 Hz / 48 kHz ниже потолка; H3/H1 = 1.22384e-9 в clean и 0.0364049
в Soft Clip (это измерение третьей гармоники, не полный THD).
Проверены кроссфейд на DC в обе стороны, сохранение и повторное восстановление
режима, оба старых формата, восстановление после prepare, extreme finite input.
Матрица 44.1/48/96/192 kHz, mono/stereo, блоки 1/64/257/1024 и bypass
выполняется для обоих режимов. Музыкальный материал в DAW не прослушивался.

## Осциллограмма и True Peak — 2026-10-17

### Общая история аудио/GR

В SignalHistory аудиопоток собирает min/max каждого выходного канала,
максимум GR и минимум Ceiling за round(sampleRate×0.002) samples. Источник —
фактические samples, записанные в буфер хоста после TP/mode mix/bypass.
Timestamp и sample rate входят в тот же кадр. Отдельные каналы сохраняют
противофазу, min/max не теряют коротких пиков при сжатии в экранный пиксель.
График показывает последние 6 s по sample clock; GR размещён над двумя
осциллограммами, без независимого GUI-clock накопления.

Кольцо 4096 кадров продолжает заполняться при закрытом GUI. Writer не ждёт
читателя. Payload и sequence markers — lock-free SC atomics: reader принимает
только кадр с одинаковым ожидаемым маркером до/после чтения. Reset не обнуляет
монотонную sequence, а сдвигает начало доступного диапазона (без ABA).
Проверены перезапись, reset, GUI clear и конкурентный reader/writer, совпадение
min/max с реальным рендером в SP и TP, включая противофазу.

### Защита true peak

Новый bool TRUEPEAK добавлен после всех прежних параметров (default OFF).
Загрузка состояния без TRUEPEAK явно устанавливает OFF, включая повторное
использование ранее включённого экземпляра. Прежние ID и нормализация сохранены.

После основного 20 ms limiter идёт отдельная 8× FIR-ступень JUCE Oversampling
(max quality, integer latency) с 1 ms lookahead и 50 ms release. Stereo Link
учитывается и этой ступенью. Внутренний потолок — Limit минус 0.75 dB:
запас учитывает интерполяцию и последующее понижение частоты.

В SP и bypass добавлена ровно такая же задержка, что у ступени TP. При 48 kHz:
960 + 48 + 65 = 1073 samples (22.3542 ms), значение сообщается хосту.
Сама основная DSP-обработка SP не менялась; после host compensation временное
положение сохраняется. Режимы не переключают задержку. TP стартует с нуля при
prepare; живое включение после idle прогревается 30 ms и затем кроссфейдится
20 ms. OFF также использует кроссфейд. Во время перехода TP не заявляется
мгновенно действующим. Резкий автоматизированный Ceiling и bypass сохраняют
свои ранее описанные ограничения; данные тесты TP относятся к устойчивым
значениям потолка, включая начало/конец тестовых сигналов.

Основной GR задержан вместе с основным аудио; GR ступени TP дополнительно
сдвигается на измеренный по импульсу пик групповой задержки downsampler
(с точностью округления до sample). Они объединяются до аудиобинов истории.
Метрика GR описывает gain обеих ступеней, не действие tanh.
Сам Soft Clip работает на исходной частоте, его алиасинг этим этапом не устранён.

### Оценка и проверка

OUT TP: отдельный 8-phase / 64-tap Blackman-windowed sinc интерполятор выхода,
не перепутанный с входом TP guard. Отрицательные уровни и противофаза
обрабатываются через модуль каждого канала; калибровка на синусе Fs/4 с
фазой π/4 выявляет peak 1 при sample peak ~0.707. Это оценка, не сертификат.

Независимый тестовый oracle использует 16 phases / 128 taps, не JUCE-апсемплер.
Матрица 84 случая: 44.1/48/96/192 kHz, Limit -6/-1/0 dBTP, синусы Fs/4,
0.45Fs, 0.49Fs, random, импульсы, бас с транзиентами, прямоугольный сигнал.
Тест допускает максимум 0.1 dB над Limit. Фактический худший результат:
0.08083 dB НИЖЕ Limit. SP fixture при Limit=-1 даёт +2.09923 dBTP,
что проверяет наличие настоящего межсэмплового превышения в тесте.
Дополнительно: TP+Soft Clip, блоки 1/1024, переключение TP на тоне 997 Hz
(ошибка <0.0002 FS относительно задержанного эталона), постоянство latency,
state roundtrip/migration, отсутствие C++ heap allocations в process/reset
и включении/выключении TP. Это не полный malloc/syscall audit и не проверка
любого возможного сигнала, внешнего ЦАП или конкретной DAW.

Принцип оценки через интерполяцию описан в
[ITU-R BS.1770, Annex 2](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-2-201103-S%21%21PDF-E.pdf).
Выбор FIR/компенсации опирается на локальный JUCE 9.0.3 и
[официальную документацию Oversampling](https://docs.juce.com/master/classjuce_1_1dsp_1_1Oversampling.html).
Соответствие стандарту BS.1770 для данного плагина не заявляется.

## Git и CI

Репозиторий github.com/mabobylev/MasterLimiterPro, основная ветка master.
Исходники, тесты, документы и tools/skills версионируются; JUCE/build исключены.

GitHub Actions собирает VST3 без установки и запускает проверки в Xvfb.

Первый CI упал в тесте перепривязки Limit: однократные sleep(40) и вызов
таймеров зависели от запуска timer thread. Теперь проверка ожидает нужный
диапазон до 2 s, обслуживая таймеры каждые 10 ms. Требуемый результат
и диапазоны не ослаблены; DSP/GUI плагина не менялись. Checkout обновлён
до официального v6 (закреплённый SHA), устраняя предупреждение Node.js 20.

Старые версии, архивы и журнал объединения удалены. Описание решений
содержит текущую архитектуру вместо противоречащих ей промежуточных этапов.
Совместимость сохранённых состояний остаётся частью действующего плагина.
