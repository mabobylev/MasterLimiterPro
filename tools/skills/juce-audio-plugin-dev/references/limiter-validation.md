# Лимитеры: проверка результата, истории и совместимости

## True peak после последнего фильтра

Проверять фактический выход после downsampling, компенсации задержки,
кроссфейда режима и выходного gain. Максимум внутреннего oversampled-буфера
не является доказательством потолка на выходе. Фильтры могут дать новый выброс.

Использовать независимую реконструкцию: другой интерполятор, больше фаз/длину,
либо внешний проверенный измеритель. Например, для 8× обработки — 16× sinc
с более длинным окном. Отдельный fixture должен показать превышение sample peak
без защиты, иначе тест может проверять только sample clipping. Протестировать
фазы высокочастотных тонов, Fs/4 со смещением фазы, импульсы, random, ступени,
пачки сигналов и их окончания, bass/transients, mono, противофазу и один канал.

Численный запас, допуск теста и статус сертификации обозначать отдельно.
Не ослаблять допуск вместо исправления выявленного выброса. Запас из одного
проекта не считать универсальным. В проверенном прототипе 0.5 dB запаса
оказалось недостаточно после FIR downsampling; при 0.75 dB 84 случая
(4 sample rates × 7 сигналов × 3 потолка) прошли независимую 16× проверку.
Это свидетельство конкретного тестового покрытия, не математическая гарантия
для любого сигнала/ЦАП и не сертификат BS.1770.

## Задержка и режимы

Учитывать основной DSP, oversampling и дополнительную защитную ступень.
Проверять задержку импульсом или низкоуровневым эталоном, включая bypass.
Если режимы переключаются при фиксированной PDC, выровнять все пути до
кроссфейда. Новую ветвь прогреть до перехода, если она не работала в фоне.
Проверять смену режима на звучащем сигнале, а не только на тишине.

Не предполагать, что oversampling пост-лимитера устранил алиасинг нелинейности,
расположенной до него. Проверять положение самой нелинейной обработки.
Если есть Stereo Link, проверить независимость тихого канала при 0%, общий
gain при 100% и сохранение выбранной семантики во вспомогательных ступенях.

## Общая шкала waveform и GR

Источник — samples, реально отправляемые хосту. На один аудиобин сохранять
отдельные signed min/max L/R и максимум GR; пиковые значения агрегировать
независимо. Не суммировать L/R для отображения: противофаза может исчезнуть.
Timestamp и sample rate должны принадлежать тому же snapshot, включая смену sr.
История в аудиопотоке позволяет открыть GUI с уже накопленным последним окном.

Для ограниченного кольца проверить чтение во время перезаписи, reset, clear и
долго закрытый GUI. Отдельные atomic поля без протокола не обеспечивают кадр.
Один проверенный вариант: atomic payload + SC sequence markers до/после записи,
проверка ожидаемого маркера до/после чтения, монотонный sequence при reset,
граница доступного диапазона для скрытия старой эпохи. Это пример протокола,
не требование использовать именно его. Для неатомарного payload простой
seqlock без гарантий владения не устраняет C++ data race.

Проверять min/max по реальному рендеру и пики при уменьшении в экранный пиксель;
синхронный график GR строить по аудио-времени, а не отдельному GUI timer.

## Старые параметры и состояния

При расширении диапазона нельзя сохранить прежнюю нормализацию того же ID
на всём новом диапазоне. Миграция XML не конвертирует внешние огибающие DAW.
Рабочий вариант — сохранить старый ID/индекс/диапазон и явно выбирать старый
путь для старых состояний, новый параметр добавить в конец. Сохранить этот
выбор при повторном save/load и перепривязать открытый GUI после restore.
Проверять не только отображение, но и активность старой автоматизации.
